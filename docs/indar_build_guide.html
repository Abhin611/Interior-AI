1. What Indar is

Indar is a free app that redecorates a room for a festival or theme. You take a photo of your own room, pick a theme (Onam, Christmas, Diwali, Halloween, Birthday or Pop-Culture) or describe what you want in words, and the app shows your room with decor in it. Everything you see in the picture is a real product from a catalog of Amazon India listings, so the whole picture can be put in an Amazon cart in one tap. Each product also has a 3D model, so you can preview it in your room with AR before buying.

The main parts

PartWhat it does
Sign-in and profileEmail and password through Supabase Auth, with optional Google sign-in. The backend checks the Supabase token on every request.
RoomsTake or pick a photo of a room. It is stored in Supabase Storage and listed in the database.
Theme or promptThree modes in one box: theme only, prompt only (for example "music posters and neon lights"), or both.
Design generationPicks real catalog products, places their cut-outs in your room photo, saves the picture and the list of what is in it. Shows real progress steps while it works.
Result pageShows the picture and the items in it, and lets you download it as a JPEG or PDF, edit the elements and open AR.
Cart bundleBuilds an Amazon India add-to-cart link containing exactly the products shown in the picture, and logs the purchase.
AR previewShows each product's .glb 3D model with model_viewer_plus.

The five principles every decision followed

1
What you see is what you can buy. No imaginary furniture. Anything in the picture must be in the cart. This one rule changed the whole design (chapter 7).
2
Free to use. Every part runs on a free tier: Supabase free plan, Colab for the optional GPU, no paid servers.
3
Easy first. One photo, one tap on a theme, and a result. The app tells the user plainly what it is doing and what went wrong.
4
Honest limits. If the catalog has nothing for a request, the app says so instead of inventing something.
5
Testable without the real thing. The AI server can be faked, the API can be called with a script, and the whole flow can be run on a laptop.

3. Getting a computer ready

These are the basic actions done once before any code was written. They are for Windows, which is what Indar was built on.

1
Install Git from git-scm.com. It also gives you Git Bash.
2
Install Python 3.12 or newer and uv (pip install uv or the installer from astral.sh).
3
Install the Flutter SDK, unzip it to a short path such as C:\src\flutter and add its bin folder to PATH. Run flutter doctor and fix what it reports.
4
Install Chrome (Flutter uses it for the web build) and, for Android, Android Studio with its SDK.
5
Create a free Supabase account, a GitHub account, and use a Google account for Colab.

Cloning and first run

git clone https://github.com/Abhin611/Interior-AI
cd Interior-AI/indar_app_backend
cp .env.example .env     # fill in the Supabase values
uv sync
Note. Never paste the database password, the service key, the JWT secret or the GPU token into chat or commit them. They live only in .env (backend) and env.json (app), both kept out of git.

4. How to run Indar, step by step

This chapter is for someone who has never run a project like this. Follow the steps in order. Nothing here needs a GPU, a paid account or any AI service: the app runs on your own computer using a free Supabase account.

The big picture. Indar has three pieces that must all be running: (1) the database and storage on Supabase's website, (2) the backend, a small Python program on your computer, and (3) the app, which you open in Chrome or on a phone. The app talks to the backend, and the backend talks to Supabase.

5. Part 1: the backend and the data

Goal: a working API with real accounts and a real product catalog before any screen exists, so every screen can be built against something true.

Step 1. Create the Supabase project

A new project gave three things: a Project URL, an anon key (safe to put in the app) and a service_role key (backend only). From Connect the Session pooler connection string was copied, because the direct connection does not work from many home networks. In Authentication, Sign In / Providers, Email the confirmation email was turned off for easy testing. In the JWT settings, the legacy JWT secret is what the backend uses to verify tokens.

Step 2. Fill in .env

SUPABASE_URL=...            SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_KEY=...    SUPABASE_JWT_SECRET=...
DATABASE_URL=postgresql+asyncpg://...   # must start with postgresql+asyncpg://

Step 3. One place for network code

api_service.dart is the only file that calls the backend, so errors are handled once. It turns problems into friendly messages: "AI is offline", "the backend is not running", or the exact reason from the server (for example "No products in our catalog match that yet"). Real progress is shown by polling /api/designs/progress/{id} with an X-Progress-Id header and updating a bar with stage names such as "Placing real products in your room...".

Step 4. Make web behave

The web build exposed three problems that the phone build hides. Each was fixed once and then checked in the browser:

  • Upload. MultipartFile.fromPath only works where dart:io exists. On the web the photo is sent from its bytes with MultipartFile.fromBytes.
  • Login page staying open. After sign-in the main gate switched pages, but the login page was still on the stack. popUntil now clears it, only on signed-in and signed-out events (not on token refresh).
  • Download button. It used to open the Amazon cart. It now opens a sheet asking JPEG or PDF. A web-only file (file_download_web.dart) saves through the browser; the phone version saves to the gallery.
Tip. Keep platform differences behind one import (file_download.dart picks the web or stub file). Screens never ask "am I on the web?".

7. Part 3: making the picture (AI first, then real products)

The first idea: let AI redecorate the room

The first design drew the room with AI. The backend picked theme products, planned where each goes (wall, hanging, floor), and sent the room photo to a GPU server that ran Dreamshaper 8 image-to-image. The GPU server speaks the same API as ComfyUI, so a real ComfyUI could replace it.

Running the GPU for free

colab/Indar_GPU_Server.ipynb starts gpu_server/server.py on a free Colab T4 and exposes it with cloudflared. The address changes every run, so the notebook registers it: it calls a SQL function set_gpu_url(token, url) in Supabase, and the backend reads the current address from the app_config table (cached for 10 seconds, with the .env value as a fallback). Nothing needs copying or restarting. A INDAR_FAKE_GPU=1 switch returns a tinted copy of the photo for testing without a GPU.

Making the AI follow the room

Plain img2img either changed too little (the room looked the same) or too much (the room was lost). Several improvements were made: furniture words first in the prompt so they are not cut off, a stronger denoise, a ControlNet (canny edges) so the room's shape is kept while it is decorated, and a rule that the user's words stay in charge in prompt-only mode.

Why it was dropped as the main path

The pictures looked like a plain room with little visible decor, and, more important, the AI drew things that do not exist in the catalog. The requirement became: anything portrayed in the image must be available to buy from the Amazon cart. An AI that draws cannot promise that.

The answer: place real products in the room photo

The design endpoint no longer draws anything. It works like this:

1
Choose the theme. The theme given, or one guessed from the prompt (infer_theme in theme_hints.py).
2
Select products. select_catalog_products takes only products that have a cut-out, scores them against the prompt keywords, and takes up to two each for Wall, Hanging and Floor. With no theme it requires at least two keyword matches, so "a big blue sofa" does not match random blue items. If nothing matches, the API answers 422 with a clear message.
3
Compose. compose_room pastes the cut-outs into the room photo (next section).
4
Save. The picture is uploaded to Storage; a Design and its DesignElements are written; a bundle is created from exactly the products shown.
5
Report progress. Stages preparing, composing, saving, matching and done are reported so the app's bar is real.

How the compositor places things

StepWhat happens
Find the floorThe photo is shrunk to 200 by 200 and averaged across the middle; the strongest brightness change between 45% and 86% of the height is taken as where the floor meets the back wall.
Wall itemsSpread along the back wall below 31% of the height, so hanging items never cover them.
Hanging itemsHung from the ceiling on a thin string in the top band, small enough to end above the wall art.
Floor itemsPlaced in front of the back wall, larger when nearer the camera, with a soft contact shadow. Rugs and mats (names containing rug, mat, carpet, rangoli) lie flat: wide and squashed for perspective.
Small thingsNames with topper, ornament, candle, diya, mini, bauble, star and the like are drawn small, because the catalog has no real sizes.
Light and shadowThe product's brightness is matched to the room's, and a soft drop shadow is added.
Same room, same layoutRandom choices are seeded from the photo bytes, so the same room always gives the same picture.
Trade-off. The result is a collage of real products, not a painted scene. It is honest and buyable, but less pretty than AI art. This was a deliberate choice.

8. Part 4: cut-outs and growing the catalog

What a cut-out is

A cut-out is a product photo with the background removed (a transparent PNG), so it can be pasted on a room photo. scripts/make_cutouts.py makes them and writes dataset/<theme>/Cutout/<ASIN>.png plus a list in dataset/cutouts.json.

How a clean cut-out is made

Many Amazon photos are a product on a plain white or light background. The script looks at the border of the photo; if at least 90% of it is a plain bright colour, it flood-fills that colour from the edges to make the background transparent. It then checks that the product takes between 5% and 88% of the picture and is not scattered. Photos that fail (for example a product in a lifestyle scene) get no cut-out and are never drawn.

cd indar_app_backend
uv run python scripts/make_cutouts.py

The rembg experiment

rembg is a small AI model that removes backgrounds from any photo. It was tried and raised the cut-outs from 31 to 66 of 90 products after a manual review, but its results were rough on busy photos (torn edges, leftover furniture, a whole house). It was removed again; the app runs on the 31 clean cut-outs only. This is recorded here so nobody has to repeat the experiment without a reason.

Adding more products

More products mean fuller rooms. Supabase's free storage allows far more than 90 products (about 37 MB for 90, so around 1,500 fit in 1 GB). The blocker is data: Amazon blocks automated page fetching, so product details cannot be scraped. Two routes are ready:

  • Put ASINs, theme and category in scripts/new_products.csv and save each product's photo as scripts/new_photos/<ASIN>.jpg. The CSV columns are asin,theme,category[,price,name].
  • Use Amazon Associates / the Product Advertising API for official product data.
uv run python scripts/add_products.py         # adds rows, builds jpg, glb and cut-out; keeps only clean cut-outs
uv run python -m app.database.seed            # loads the new rows
uv run python scripts/setup_storage.py        # uploads the new files

About 30 real ASINs found by web search are already in new_products.csv but none were added yet, because their photos could not be fetched.

9. The routine for every change

1
Make one small change. One idea per commit.
2
Test the backend with a script. Restart uvicorn (it caches the cut-out list at start) and run the API test for every theme and prompt mode. Check the status codes and that the cart equals the picture.
3
Look at the result. Open the produced picture. Counting items is not enough; check overlaps, sizes and where things sit.
4
Check the app in the browser. Rebuild the web app only if Flutter code changed, then sign in, upload a photo, generate and download.
5
Commit and push. A short message that says what changed and why. Commits show only the account owner as author.

Useful commands

uv run uvicorn app.app:app --port 8000          # start the API
uv run python -m app.database.seed              # (re)load themes and products
flutter build web --dart-define-from-file=env.json
python -m http.server 5000                      # serve build/web
git add -A && git commit -m "..." && git push

Windows gotchas that cost time

  • Run background servers with their input closed (< /dev/null) or they can hang.
  • To free a stuck port 8000 use PowerShell: Get-NetTCPConnection -LocalPort 8000 then Stop-Process.
  • Avoid long scripts with nested quotes in one shell line; write them to a file instead.

10. The toughest problems, and how each was solved

1. "Imaginary" pictures

Symptom. AI drew furniture and decor that were not in the catalog, or drew nothing visible.
Cause. A generative model invents; it cannot be limited to a product list.
Fix. Stop drawing. Paste real cut-outs into the user's photo, so the picture and the cart are the same list by construction.

2. The GPU server crashed on the scheduler

Symptom. ValueError about final_sigmas_type from the DEIS scheduler.
Cause. The model's saved scheduler config does not suit newer diffusers.
Fix. Build the scheduler explicitly (DPM-Solver++, with algorithm_type, solver_order and final_sigmas_type set). The notebook had cached the old file, so Colab had to be re-run.

3. Upload failed on the web

Symptom. "Unsupported operation: MultipartFile is only supported where dart:io is available".
Fix. Send the photo as bytes with MultipartFile.fromBytes.

4. The login page did not close

Symptom. After signing in the page stayed.
Fix. popUntil on signed-in and signed-out events only. Popping on every auth event also popped pages during token refresh.

5. A patch went to the wrong function

Symptom. A 500 error: analyze_room() got an unexpected keyword argument 'user_id'.
Cause. A scripted edit added the new arguments to a different function with a similar signature.
Fix. Correct both signatures. It was found only by running a real generation, which is why a real end-to-end test is part of the routine.

6. Prompt-only mode returned unrelated products

Symptom. "a big blue sofa" returned items with "Blue" in their name.
Fix. With no theme, require at least min(2, number of words) keyword matches; otherwise reply 422 with a friendly message.

7. Items overlapped and had silly sizes

Symptom. Hanging items covered wall art, a rug was a thin line, a tree topper was bigger than a person.
Fix. Separate vertical zones for hanging and wall items, a flat-item rule that only applies to wide pictures, and small-by-name rules.

8. Amazon blocked product page fetching

Symptom. 29 of 30 new product pages could not be read.
Decision. Do not work around the block. Add a route that uses the user's own saved photos, and name the official option (Associates API).

9. Too-rough cut-outs from the AI remover

Symptom. rembg gave jagged edges and leftover objects.
Decision. Remove it and keep only clean, plain-background cut-outs, accepting emptier rooms.

10. A tool that blocked a harmless command

Symptom. A safety check blocked a pointless rm on a system path.
Lesson. The block was right; the command had no purpose and was dropped.

11. Interview questions and how to answer them

What does Indar do, in one breath?

You photograph your room, pick a festival theme or describe what you want, and the app shows your room with real products from an Amazon catalog placed in it. You can put exactly those products in a cart or preview them in AR.

Why not just use AI image generation?

I tried it first, with Stable Diffusion and ControlNet on a free Colab GPU. It looked nice but drew things that could not be bought. The key requirement became that everything in the picture is a real catalog product, so I composite cut-outs of real products instead.

How do you guarantee the cart matches the picture?

The same list of products is used for both. The compositor receives the products and returns their placements; the bundle is built from those same product ids. An API test checks that the bundle equals what is shown.

How does the compositor decide where things go?

It finds the floor line from brightness changes in the photo, then uses three zones: wall art on the back wall, hanging items from the ceiling, floor items in front of the wall with shadows. Rugs lie flat, small items are drawn small, and a seed from the photo makes the layout repeatable.

Why Supabase?

Auth, Postgres and file storage in one free plan. The backend verifies the Supabase token, so I did not write my own login.

Why FastAPI?

It is quick to write, async, validates input with Pydantic and documents itself. Heavy image work runs in a thread (asyncio.to_thread) so the server stays responsive.

How is the app kept free to run?

Free Supabase plan, no paid GPU (the AI path is optional), cut-outs are made once ahead of time, and composing a picture takes a few seconds on a CPU.

How do you handle a request the catalog cannot serve?

The API replies 422 with a clear message such as "No products in our catalog match that yet", and the app shows it. It never invents a product.

How did you show real progress?

The backend stores the current stage in memory under a progress id. The app sends the id in a header and polls an endpoint, then moves a bar through stages with plain-language names.

What was your hardest bug?

A good answer is chapter 10, problem 5: a scripted patch changed the wrong function, the unit-style checks passed, and only a real end-to-end generation exposed it. That is why I always run a real request after a change.

What would you do next?

Host the backend for free, add many more products with clean photos so every theme fills a room, add real product sizes for correct scale, and test AR and the camera on a phone.

What are the limits you are honest about?

Only 31 of 90 products have clean cut-outs, so some themes are sparse; sizes are estimated; the picture is a collage rather than a painted scene; AR and gallery saving are not yet tested on a phone.
